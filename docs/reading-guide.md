# Как изучать проект «Календарь звонков» (путеводитель)

Статус: готово
Дата: 2026-09-01
Зачем: быстро погрузиться в проект — понять, что строим, чем, как устроено,
где мы сейчас. Маршрут покрывает всё: что было в репозитории изначально,
входное задание, что добавил агент, память проекта.

---

## Порядок чтения (от общего к частному)

### Блок A — «Что здесь было» (основа проекта, не агент)

| Шаг | Что читать | Что это, зачем |
|---|---|---|
| A1 | `README.md`, `.github/workflows/README.md` | Визитка проекта + объяснение автотестов Хекслета (поэтому `hexlet-check.yml` нельзя трогать) |
| A2 | `git log --oneline` | История по коммитам: становление проекта (hexlet-check → контекст → GitHub-интеграция → память). При желании `git show <SHA> --stat` |
| A3 | `.github/workflows/` (opencode*.yml) | GitHub-интеграция агента: `/oc` в issues/PR (только владелец, key в secrets, share:false); triage — анти-спам; review — авторевью PR; schedule — расписание |
| A4 | `.opencode/skills/` + `skills-lock.json` *(локально, в git не входят)* | Инструменты агента: `ru-text` (рус. текст), `supabase-postgres-best-practices` (SQL), `grill-me` (стресс-тест планов), `gh-fix-ci` (разбор падающих CI-проверок) |

## Минимальный путь (мало времени)

`A1` → `B1` → `C1` (§1–2, §10–11) → `C2` → `D2`

## Кому что читать

- **Нужна суть продукта**: B1, C1 (§1–4), C2
- **Нужно продолжить разработку**: D1, C3 (план), C2 (спека), C1 (§5, §9–11), D2
- **Интересует настройка агента/GitHub**: A3, A4, D6
- **Интересует память/история**: A2, D3–D5

---

## Как ориентироваться в `docs/project-understanding.md`

Это главный документ. Разделы читать именно в таком порядке (каждый опирается на предыдущий):
§1–2 (зачем и термины) → §3 (UI) → §4 (архитектура) → §5 (стек) → §6 (ссылки) →
§7 (план + требования) → §8 (открытые вопросы) → §9 (детальный план) →
§10 (структура) → §11 (решения).
