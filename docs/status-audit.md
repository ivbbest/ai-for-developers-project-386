## 5. Замечания по git-гигиене

### Локальные ветки
После мержа PR локальные ветки остались (не удалены); указан **tip** ветки
(не merge-коммит main). Все сверки предковости выполнены в локальном клоне
(`git cherry`, `merge-base`); tip `69fa18e` на GitHub отсутствует (ветка не
пушилась дальше `9140a45`) и в CI-клоне не воспроизводится:
- `docs/audit` (dbaad61) — влита в main
- `docs/audit-round2` (c1a81ce) — влита; main продолжен коммитом 9dc96f1
- `docs/review-finalization` (8a232a3) — влита через PR #2 (merge 92ff6f3)
- `docs/audit-fixes` (69fa18e) — PR #3 влита (merge 3fd81f9); tip **не является
  предком main**: тот же патч лёг в main отдельным коммитом c1a81ce
  (`git cherry main docs/audit-fixes` → «-», деревья идентичны)

**Рекомендация:** удалить слитые ветки (на усмотрение пользователя):
```bash
git branch -d docs/audit docs/audit-round2 docs/review-finalization
# docs/audit-fixes: не предок main, -d откажет («not fully merged»);
# патч уже в main (c1a81ce) — безопасно удалить с -D:
git branch -D docs/audit-fixes
```

### Remote-ветки
- `remotes/origin/docs/audit-fixes` (9140a45) — предок main (слита через PR #3),
  но remote-ветка на GitHub осталась
- `remotes/origin/docs/review-finalization` — предок main (слита через PR #2),
  remote тоже осталась

**Рекомендация:** `git fetch --prune` убирает только те tracking-ссылки, чьи
ветки уже удалены **на remote**. Сначала удалить их на GitHub (только
пользователь), затем prune:
```bash
git push origin --delete docs/audit-fixes docs/review-finalization
git fetch --prune
```
