Прочитай перед началом работы. Правила и факты — в файлах, а не в диалоге
(каждая сессия стартует с чистого контекста).

## Секреты и `.env` (НЕ читать)

- `.env` и секреты (API-ключи, пароли, токены) — **вне контекста**, считать
  несуществующими. Смотреть/менять/создавать может только пользователь; агент — никогда.
- **Запрещено**: читать/подставлять/выводить/логировать значения секретов,
  писать их в файлы, коммиты, задачи, issues/PR.
- Допустимо знать только *имена* переменных (например `ANTHROPIC_API_KEY`);
  значения — никогда. Ключи в GitHub Actions secrets добавляет только пользователь.

## Границы действий

> **IMPORTANT: git commit/push — только пользователь.** Агент готовит изменения
> в рабочем дереве и показывает итог (`git status --porcelain`, `git diff --stat`),
> но не коммитит и не пушит. `gh`/git-команды записи — не выполнять.

- `git clone`/`fetch`/`status`/`diff`/`log` (чтение) — можно.
- **В сообщениях коммитов не использовать слова/паттерны в стиле ИИ** — например
  «AI», «ИИ» и подобное; коммиты нейтральные (правило пользователя).
- `hexlet-check.yml` — не менять (удаление/правка ломает автотесты курса).
- Дополнительные workflow (например `opencode.yml`) — только по явному запросу
  пользователя; инструкцию по ручной настройке — в `.agents/tasks.md`.

## Память сессии

- **Журнал «Что сделано»** — `.agents/context.md`: записи «дата + факт + SHA» (1–2 строки).
- **Индекс фактов** — `.agents/mem/MEMORY.md`: 1 строка на запись, категории
  `user`/`feedback`/`project`/`reference`; детали — топиками рядом.
- **Коррекции пользователя** записывать **в моменте**, только добавление
  (append-only), формат `YYYY-MM-DD | правило | источник`.
- **При старте задачи** — читать `MEMORY.md` (индекс) и актуальные топики;
  в конце — чек-лист закрытия: обновить `context.md`, `MEMORY.md`,
  `.agents/tasks.md`, показать список обновлённого.

## Принципы работы

- **Верифицируй работу, а не декларируй.** После правки — фактический результат
  проверок (вывод/exit-code), а не «сделано».
- **Пойми последствия до правки (impact analysis).** Найди все затронутые места
  (grep), оцени риск; неясно — сначала исследование.
- **Ревью диффа перед сдачей.** Ветки с логикой (>3 файлов) просматривать свежим
  контекстом (субагент читает diff и критерии); микро-правки — без ревью.
- **Исправляй причину, а не следствие.** Не подавляй исключения и не ставь
  таймауты наугад; корень вне зоны — тикет + ссылка в коде.
- **Комментируй причины, а не факты** (why-comments): «почему», не «что».
- **Игнорируй чужие изменения.** Правки, которые не делал, считай осознанными;
  в чужие файлы — только по явной просьбе.
- **Переиспользуй, не дублируй.** Если есть готовое (эталон, шаблон, функция) —
  используй его, а не копируй.
- **Чекпоинты при многошаговых правках.** Шагами: фиксация → проверка → зелёный
  (коммит-чекпоинт, но коммит делает пользователь) → красный (откат `git restore`).
